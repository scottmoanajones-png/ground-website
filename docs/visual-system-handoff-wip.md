# Ground Visual System Handoff

**Status:** WIP  
**Audience:** Ground team, client stakeholders, future external designers  
**Purpose:** Organize the current thinking around how Ground visuals should be conceived, reviewed, and produced so future work stays on-brand and production-ready.

## What this is

This document is the beginning of a client-handoff guide for Ground's visual system.

It is not final yet. Some of the principles below are already well-supported by the live site and the existing grid system. Others are strong working hypotheses that still need more testing before they should be treated as locked rules.

For now, this document should be used as:

- a shared explanation of what is working
- a record of what has not been working
- a filter for evaluating future visual concepts
- a base for a later polished client-facing handoff

## Current diagnosis

Ground does **not** currently have a lack-of-tools problem.

The project already has:

- a strong hero reference
- a working grid-object renderer
- a working stream-grid renderer
- authored platform shapes and scenes
- motion research
- brand guidance
- a production website where ideas can be tested quickly

The bigger issue is that the visual system has not been fully operationalized into a repeatable handoff method.

In practice, that has meant some section visuals ask too much of a single image at once. A section visual may try to be:

- a metaphor
- a category diagram
- a product explanation
- a motion study
- a polished composition

When too many jobs pile into one asset, the result often becomes technically interesting but visually underpowered.

## Core conclusion

The path forward is not just "better prompts" and not just "better designer handoff."

The missing layer is a clearer **scene architecture** for Ground visuals.

That means every future visual should have a more explicit contract:

- what it must communicate in one second
- what the silhouette must be
- what motion is responsible for
- what belongs in the composition versus the renderer
- what "production-ready" means before approval

## What the hero teaches

The hero is currently the best example of Ground's visual language working at a high level.

Why it works:

- it has one dominant form
- the silhouette is legible immediately
- the composition feels large and intentional
- motion supports the idea instead of compensating for weak structure
- contrast is controlled
- the metaphor is strong but not over-explained

This should be treated as the benchmark for future section visuals.

Not every section needs to look like the hero, but every section visual should match its level of clarity and inevitability.

## Ground visual principles

These are the clearest working principles so far.

### 1. Structure first

Ground visuals should feel infrastructural, not decorative.

The viewer should first perceive:

- form
- order
- hierarchy
- routing

Only after that should they notice texture, motion nuance, or secondary metaphor.

### 2. Silhouette matters more than detail

If a visual does not read in broad silhouette, more internal detail will not save it.

Strong Ground visuals should still feel intentional when:

- blurred
- paused
- seen at half size
- glanced at while scrolling

### 3. Motion reveals structure

Motion should not be the main source of meaning.

Motion should:

- activate
- route
- gather
- pulse
- restack
- clarify relationships

Motion should not be used to hide a weak still frame.

### 4. One visual should have one primary job

A visual can support multiple ideas, but it needs one primary responsibility.

Examples:

- hero: transform floating signal into grounded infrastructure
- value card: show one behavior
- platform scene: show Ground as the connective infrastructure between different platform types

If a visual has four equal jobs, it usually has no clear job.

### 5. The renderer is not the concept

The renderer is a delivery system, not the design idea.

Future work should start by naming:

- the scene archetype
- the silhouette
- the motion motif
- the communication goal

Only then should the implementation path be chosen.

### 6. Green should feel earned

Green should mark activation, signal, or live connectivity.

It should not be sprayed across a composition for energy.

### 7. Big forms beat busy fields

Ground can absolutely use fields and grids, but the strongest moments usually come from a clear dominant object, path, or structural relationship inside that field.

## Brand expression levels

This is a more global way to think about the system.

Not every Ground touchpoint should express the brand at the same intensity.

Instead of asking whether a page is "on brand" in one single way, it is more useful to ask:

- how loud should the brand be here
- how much metaphor is needed here
- how much motion is appropriate here
- how much of the grid system should be visible here

For now, the clearest model is three expression levels:

### 1. Loud

Use when the brand itself needs to do persuasive work.

This is where Ground should feel most distinctive, ownable, and memorable.

Typical traits:

- strong metaphor
- strong stage composition
- major visual hierarchy
- visible grid logic
- expressive motion when earned
- clear use of signature perspective ideas

Good candidates:

- homepage hero
- major campaign moments
- flagship deck covers
- key client presentation visuals

Loud does **not** mean noisy.

It means the brand expression is highly visible and doing real strategic work.

### 2. Middle

Use when a surface still needs visible brand presence, but clarity and utility share the stage.

Typical traits:

- one clear branded scene or pattern
- productive motion more than expressive motion
- visible but restrained metaphor
- structural use of the grid, not theatrical use
- strong still-frame legibility

Good candidates:

- homepage supporting sections
- platform section
- value explainers
- diagrams in decks
- stronger product-marketing modules

Middle is likely where most future Ground visuals will live.

### 3. Quiet

Use when information, trust, and usability matter more than overt brand spectacle.

Typical traits:

- editorial typography
- spacing and hierarchy doing most of the work
- minimal or no major scene behavior
- grid absent, subtle, or purely structural
- little to no expressive motion

Good candidates:

- FAQ
- contact
- legal pages
- founder bios
- utility surfaces

Quiet should still feel like Ground.

It should feel calm, assured, and coherent without needing a major visual event.

### Why this matters

This model keeps the system flexible.

It prevents two common failures:

- over-branding quiet surfaces
- under-branding moments where the brand should be most memorable

It also makes future commissioning easier because a collaborator can be told:

- this asset should be `loud`
- this page should be `middle`
- this flow should remain `quiet`

without prescribing one exact scene solution.

## Recommended visual workflow

This is the first version of a repeatable process for future Ground visuals.

### Step 1. Define the scene brief

Before making a visual, define:

- section name
- expression level (`loud`, `middle`, `quiet`)
- audience
- message
- primary job of the visual
- required still-frame read
- required motion read
- desired emotional register

### Step 2. Choose the visual family

Ground currently has three visual families:

- `hero-field`
- `grid-object`
- `stream-grid`

Choose the family based on the job of the visual, not based on which tool happens to be easiest in the moment.

If the touchpoint is `quiet`, the correct answer may be that it does not need a scene family at all.

### Step 3. Name the scene archetype

Every visual should be describable in plain language before execution.

Examples:

- hub and spoke
- ring and core
- district and corridor
- monolith and route
- field and anchor

If the archetype cannot be named clearly, the concept is probably still too vague.

### Step 4. Lock the still frame

Before polishing motion, check:

- is the silhouette strong
- is the composition large enough
- is the focal hierarchy obvious
- does it look intentional when paused

### Step 5. Add motion only after the still frame works

Motion should be layered onto a strong structure.

Ask:

- what activates
- what routes
- what holds
- what settles
- what repeats

### Step 6. Review against production criteria

Before approval, the visual should pass:

- clear 1-second read
- strong silhouette
- controlled palette
- on-brand motion
- desktop and mobile viability
- compatibility with reduced motion

## Production-ready criteria

This section should become stricter over time, but the current pass/fail bar is:

### Composition

- One dominant visual idea is obvious.
- The asset feels sized for the section, not merely inserted into it.
- The contrast structure is intentional.

### Form

- The silhouette is readable quickly.
- Height and mass distribution feel designed, not noisy.
- Major shapes do not collapse into texture.

### Motion

- Motion clarifies the structure.
- The animation can be described in one sentence.
- The first cycle is understandable without repeated viewing.

### Brand fit

- The asset feels credible, elegant, and assured.
- It does not drift into crypto spectacle, glow-heavy futurism, or generic SaaS illustration.
- It feels like infrastructure.

### System fit

- It belongs to one of Ground's visual families.
- It reuses the motion and shape vocabulary instead of inventing a disconnected language.
- It can be handed off without needing the original designer to explain every choice verbally.

## Platform section lessons

The platform section exposed the current gap especially clearly.

### What was weak before

- The visual was trying to carry too much metaphor by itself.
- The silhouette was less distinct than it needed to be.
- The scene read more as a dense field than a strong infrastructural statement.
- The composition was not giving the visual enough stage presence.

### What improved in the latest pass

- stronger authored silhouettes
- clearer scene hierarchy
- a more intentional contrast stage
- motion used to express Ground as connective infrastructure
- better continuity between section copy and visual logic

### What still needs research

- how abstract vs literal platform categories should feel
- whether platform visuals should privilege category distinction or one unified ecosystem view
- how far section visuals should go in carrying metaphor before copy takes over
- whether some sections should use simpler scene archetypes than initially expected

## Open questions

These are still active questions, not settled policy.

- How many reusable scene archetypes does Ground really need?
- Which ideas should live as authored shapes versus procedural profiles?
- How much brand metaphor should be visible in every section, versus reserved for hero and a few anchor sections?
- Should future external designers begin in Figma, in grid tools, or in written scene briefs first?
- What is the minimum package needed for a third party to produce good new visuals without direct team guidance?

Before this becomes an official client document, the next step should be to gather stronger proof in a few areas:

- Capture before/after examples showing why certain visuals fail and others work.
- Define a lightweight handoff stack:
  scene brief -> still frame -> motion note -> production implementation

## Comparison against common framework patterns

Looking at common brand-guideline and design-system structures, Ground is already strong in some areas and still thin in others.

### Where Ground is already strong

- **Core metaphor:** stronger than many brand guides because the name, logo, copy, and product all align.
- **Visual thesis:** the top-down / isometric split is unusually clear and distinctive.
- **Do / don't clarity:** strong negative guidance already exists.
- **Tone of voice direction:** the credible / elegant / assured framing is useful and memorable.
- **Prototype references:** there is already a working bridge between rules and implementation.

### Where Ground is only partially defined

- **Audience depth:** high-level audience groups exist, but not enough detail about what each audience needs to feel or understand first.
- **Motion system:** there are good instincts, but not yet a formal taxonomy of motion types, durations, intensity, and fallback behavior.
- **Channel adaptation:** rules for homepage are stronger than rules for decks, diagrams, social, investor material, or product UI.
- **Example library:** there are not yet enough side-by-side examples of approved, borderline, and rejected work.
- **Review governance:** the system has rules, but not yet explicit ownership, update cadence, or approval authority.

### Where Ground still has clear gaps

- **Accessibility guidance:** reduced motion, contrast discipline, readability, and assistive-use considerations should be explicit.
- **Asset operations:** a future client needs a clearer map of where to find logos, scenes, renderers, templates, and current source files.
- **Commissioning workflow:** outside designers need a repeatable process from brief to approval, not just brand principles.
- **Taste adjudication:** there is not yet a simple method for resolving subjective disagreements beyond conversation.
- **Cross-channel examples:** the brand needs to show how the rules flex without breaking across different formats.

## Draft motion grammar

This section is still WIP, but it is the clearest first pass at how motion should behave across the Ground system.

### Core principle

Motion exists to clarify state, structure, and activation.

It should not exist primarily to decorate, entertain, or compensate for a weak still frame.

### Motion roles

Ground motion currently seems to fall into five useful roles:

- `reveal`
- `route`
- `activate`
- `settle`
- `signal`

These roles should become the base vocabulary for future review and handoff.

### 1. Reveal

Reveal motion changes understanding.

Examples:

- top-down to isometric shift
- height emerging from a previously flat grid
- latent infrastructure becoming tangible

Use reveal when:

- the user is meant to understand the same system differently after motion
- the motion is the brand moment
- the transition carries real metaphorical meaning

Do not use reveal when:

- the shift is only stylistic
- the second view does not add meaning
- the same effect is repeated across too many sections

### 2. Route

Route motion shows that Ground is organizing flow through infrastructure.

Examples:

- traffic moving through a path
- packets feeding into a node and redistributing
- a circuit or pathway becoming live across the grid

Use route when:

- the visual's job is to show connectivity or distribution
- the section is about infrastructure behavior
- movement between nodes is the core point

Route motion should feel:

- orderly
- directional
- legible
- controlled

It should not feel:

- swirly
- chaotic
- noisy
- liquid

### 3. Activate

Activate motion marks the moment potential becomes live.

Examples:

- a single green event turning on
- a block or path moving from idle to active
- a localized pulse confirming connection

Use activate when:

- the visual needs a clear before/after state
- green is being used as a mark of liveness
- a single event should become the focal point

This is one of the most important Ground motion types because it directly supports the floating-to-grounded metaphor.

### 4. Settle

Settle motion resolves a structure into order.

Examples:

- scattered blocks aligning into a grid
- forms stacking into a coherent arrangement
- traffic normalizing into steady rhythm after handoff

Use settle when:

- the idea is organization
- the visual begins dispersed and ends coherent
- the movement is about confidence, not surprise

Settle motion should feel calm and inevitable.

### 5. Signal

Signal motion is the lightest-weight motion behavior.

Examples:

- subtle pulsing
- small state shimmer
- restrained hover or emphasis cues

Use signal when:

- the structure already works without motion
- the goal is to confirm activity, not explain it
- the moment is secondary to the main composition

Signal motion should almost never become the hero of the section.

### Productive vs expressive motion

Ground should likely divide motion into two categories:

#### Productive motion

Purpose:

- explain state
- guide the eye
- preserve continuity
- clarify interactions

Examples:

- route traces
- small activation pulses
- section reveals
- accordion and navigation behavior

This should be the default motion mode for most of the website.

#### Expressive motion

Purpose:

- deliver the core brand moment
- reveal metaphor
- create a memorable signature transition

Examples:

- the hero camera shift
- a major scene reveal where understanding changes

This should be rare and intentional.

Not every section deserves expressive motion.

Expression level should influence motion choice:

- `loud` can justify expressive motion
- `middle` should usually rely on productive motion
- `quiet` should usually minimize motion to what is necessary for clarity

### Hero-only motion

Some motion ideas should probably remain reserved for hero or only appear in heavily adapted form elsewhere.

Current candidates:

- the most dramatic top-down to isometric reveal
- the most theatrical dark/light stage shift
- any transition that functions as the primary brand signature

This matters because repeated signature moves weaken the hierarchy of the site.

### Motion hierarchy rules

- one focal event per scene
- supporting motion must reinforce the focal event
- simultaneous equal-priority animations should be avoided
- if motion can be removed with no loss of meaning, it is probably too decorative

### Rhythm and pacing

Ground motion should feel:

- confident
- measured
- engineered
- smooth

It should not feel:

- bouncy
- springy
- playful
- frantic

### Green and motion

Green should often appear through motion, not just through fill.

Preferred uses:

- activation event
- live path
- connected node
- one emphasized yield state

Avoid:

- many equal green flashes
- constant pulsing across the entire field
- treating green as ambient energy everywhere

### Reduced motion

Every major scene should remain understandable with motion removed or simplified.

Reduced-motion behavior should usually preserve:

- still-frame hierarchy
- active vs inactive state
- route legibility
- section readability

Reduced-motion behavior should usually remove:

- repeated pulses
- camera theatrics
- non-essential shimmer

### Open motion questions

- Which motion roles should map to named renderer behaviors?
- Which motion patterns are section-specific versus system-wide?
- How much camera motion should exist outside the hero?
- What duration and easing ranges best fit "credible, elegant, assured"?

## Draft applications matrix

This section is meant to show how the system flexes across formats and section types.

### Principle

Not every touchpoint needs the full Ground visual language.

The system should scale from:

- quiet editorial pages
- to structured product diagrams
- to major signature brand moments

The easiest shorthand is:

- `loud` = brand-forward
- `middle` = system-forward
- `quiet` = information-forward

### Expression level map

This is a first-pass classification, not final policy.

- homepage hero: `loud`
- homepage proof strip: `middle`
- homepage value section: `middle`
- homepage platform section: `middle`
- homepage use cases: `middle`
- about page hero: `quiet`
- founder bios: `quiet`
- contact: `quiet`
- FAQ: `quiet`
- legal pages: `quiet`
- flagship deck cover moments: `loud`
- explanatory diagrams: `middle`
- social stills: `middle` or `loud` depending on purpose

### 1. Homepage hero

Role:

- establish brand thesis
- introduce the grid
- deliver the main expressive motion moment
- prove Ground as infrastructure, not just software

Expression level:

- `loud`

Should emphasize:

- strongest metaphor
- strongest contrast stage
- most legible silhouette
- signature perspective logic

Should avoid:

- clutter
- secondary metaphors competing with the main read
- too many equal moving elements

### 2. Homepage supporting sections

Role:

- extend the system without competing with hero
- explain specific product ideas
- provide one focused visual argument per section

Expression level:

- usually `middle`

Should emphasize:

- one scene, one job
- productive motion over expressive motion
- cleaner still-frame reads
- continuity with the hero without imitation

Should avoid:

- copying the hero's exact staging
- repeating the same reveal logic too literally
- turning every section into a mini-spectacle

### 3. Platform section

Role:

- explain Ground as connective infrastructure
- translate audience/platform variety into one coherent system

Expression level:

- `middle`

Should emphasize:

- one infrastructural metaphor
- strong legible routing
- Ground as bridge, interchange, or reference point
- traffic logic over decorative diversity

Should avoid:

- too many discrete scenes
- category-by-category over-illustration
- animation where nothing is clearly the hero

### 4. Value and product-explainer sections

Role:

- show one product behavior at a time
- make the product feel clear, efficient, and controlled

Expression level:

- `middle`

Should emphasize:

- simpler scene archetypes
- data or state meaning
- compact productive motion
- easy still-frame comprehension

Should avoid:

- carrying too much abstract metaphor
- needing long explanation to understand the image

### 5. About, contact, and FAQ pages

Role:

- maintain brand continuity with minimal visual burden
- let copy, hierarchy, and spacing do most of the work

Expression level:

- `quiet`

Should emphasize:

- editorial typography
- calm surfaces
- mono labeling
- minimal or no major scene work

Should avoid:

- forcing a large brand visual where it is not needed
- adding motion simply for consistency

### 6. Diagrams and product explainers

Role:

- make Ground legible to clients, partners, and technical stakeholders

Expression level:

- usually `middle`

Should emphasize:

- floating vs grounded logic
- route clarity
- explicit nodes and flows
- reduced metaphor ambiguity

Should avoid:

- atmospheric abstraction
- beautiful-but-vague scenes

### 7. Decks and sales material

Role:

- carry the brand into persuasion contexts without requiring full website interactivity

Expression level:

- mixed

Suggested split:

- cover / opener moments: `loud`
- explanatory middle slides: `middle`
- dense operational slides: `quiet`

Should emphasize:

- still-frame strength
- editorial composition
- diagram clarity
- a few reusable branded scenes

Should avoid:

- concepts that only work once animated
- layout systems that collapse outside the website

### 8. Social, stills, and lightweight marketing surfaces

Role:

- preserve recognition in compressed formats

Expression level:

- `middle` by default
- `loud` for signature campaign moments

Should emphasize:

- logo discipline
- color restraint
- one strong form
- clear use of mono and serif roles
- one shared animation palette family with light/dark surface variants rather than separate scene-specific color systems

Should avoid:

- dense grid scenes that lose readability at small sizes
- subtle motion-dependent meaning

### 9. Mobile surfaces

Role:

- preserve comprehension first
- preserve brand second

Expression level:

- depends on touchpoint, but often one step quieter than desktop

Should emphasize:

- strong cropping
- reduced scene complexity
- fewer competing elements
- typography and information hierarchy

Should avoid:

- forcing desktop-scale visuals into narrow spaces
- requiring motion to understand the section

### 10. Future external design commissions

Role:

- enable outside collaborators to make good decisions without constant live translation from the Ground team

Should require:

- a written brief
- a declared scene family
- a still-frame concept
- a motion note
- a pass against anti-patterns

Should avoid:

- starting directly in polished execution
- relying on aesthetic taste alone without scene logic

### Cross-application consistency checks

Any new application of the system should answer:

- What is the primary message here?
- Does this touchpoint need expressive motion, productive motion, or no motion?
- Is the grid structural, explanatory, or unnecessary?
- What is the single dominant visual idea?
- What part of the Ground metaphor is actually doing work here?

### Open application questions

- Which touchpoints deserve the full grid language and which only need hints of it?
- How many reusable still scenes should be standardized for decks and social?
- What is the minimum viable Ground signature on low-motion or no-motion surfaces?

## Intended handoff model

This is the operating assumption for the future client-facing system.

The document should be high-level enough that a client or outside collaborator can use it with different tools and still arrive at recognizable Ground outcomes.

The intended flow is:

1. A human defines the communication goal.
2. The collaborator or LLM reads this document.
3. The collaborator identifies the correct expression level: `loud`, `middle`, or `quiet`.
4. The collaborator selects the right visual family, scene logic, and motion role if a scene is needed.
5. The collaborator uses Ground tools such as the grid creator, renderer, or animation-capable implementation path to produce the asset.
6. The asset is reviewed against brand fit, still-frame quality, motion quality, and application fit.
7. The approved asset is handed into web, deck, or other production surfaces.

### What this means for the document

The final client-facing version should stay:

- strategic enough to guide many ideas
- specific enough to reject bad ones
- modular enough for LLM use
- practical enough to support production handoff

It should **not** become so specific that it only describes the current website.

It should **not** become so abstract that every collaborator still has to guess what Ground means.

### What an LLM should be able to get from this document

At minimum, an LLM or outside designer should be able to determine:

- what Ground is trying to express
- how intensely the brand should be expressed on this surface
- whether a visual is needed at all
- which visual family is appropriate
- which motion role is appropriate
- what should count as off-brand
- what must be true before an asset is considered usable

### What supporting materials should exist alongside this document

This document should eventually be paired with:

- a scene example library
- approved still references
- approved motion references
- source-of-truth asset locations
- tool instructions for the grid creator / renderer
- implementation notes for web production

The taste profile defines judgment.

The supporting materials make that judgment executable.
